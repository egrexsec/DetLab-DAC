# DetLab Knowledge Base

This directory is the home for DetLab-authored documentation artifacts.

DetLab documentation is not optional polish. It is part of the deliverable.

## Workflow

**Learn → Lab → Investigate → Detect → Hunt → Document → Publish**

## Directory structure

- `learning-paths/` — educational progress and concept mastery
- `labs/` — hands-on exercises, validation work, and technical experimentation
- `incident-response-case-studies/` — investigations documented like real incidents
- `threat-hunts/` — proactive hunting workflows, hypotheses, and findings
- `detection-engineering/` — reusable detections and detection notes
- `aws-security-learning/` — AWS security study notes with defender context
- `flaws-cloud/` — flaws.cloud case studies
- `flaws2-cloud/` — flaws2.cloud case studies

## Content rule

Each entry should function as one or more of the following:

- learning notes
- operational runbook
- detection reference
- threat hunting guide
- portfolio artifact

If an activity cannot yet produce one of those outcomes, keep working until it can.

## Quality rule

Every entry should explain:

- what happened
- why it matters
- attacker use or abuse path
- defender detection approach
- defender investigation approach
- defender response approach
- improvement actions

## Template rule

Start with the matching DetLab lane and structure from the website and repository folders, then tailor it to the activity instead of inventing a brand-new format each time.
